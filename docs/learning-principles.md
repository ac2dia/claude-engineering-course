# 학습 원칙

## 1. Claude가 중심이고 결제는 실습 재료다

권장 콘텐츠 비중은 다음과 같다.

| 영역 | 비중 |
|---|---:|
| Claude의 작동 개념과 한계 | 25% |
| Claude Code 사용 및 작업 방식 | 45% |
| 결과 검증과 자기 판단 | 20% |
| 주문·결제 도메인 지식 | 10% |

모든 레슨은 결제 기능보다 Claude 역량을 제목과 학습 목표에 먼저 드러낸다. 결제 사례를 다른 도메인으로 바꾸어도 학습한 역량을 재사용할 수 있어야 한다.

## 2. 사실, 설명, 권장사항을 구분한다

콘텐츠는 다음 범주를 명확히 구분한다.

- 공개된 사실: 공식 문서로 확인할 수 있는 내용
- 개념적 설명: 이해를 돕기 위해 단순화한 정신 모델
- 실무 권장사항: 과정에서 권장하는 작업 방식
- 주의사항: 제품 버전이나 회사 정책에 따라 달라지는 내용

Claude의 공개되지 않은 내부 구현을 추측하지 않는다. 일반적인 LLM 원리와 Claude에 관해 공식적으로 확인된 내용을 구분한다.

## 3. 조사와 구현을 분리한다

처음부터 코드 생성을 요청하지 않는다. 학습자는 먼저 관련 코드, 호출 흐름, 제약, 기존 테스트와 확인되지 않은 가정을 조사한다. 그다음 계획을 리뷰하고 작은 단위로 구현한다.

기본 작업 루프는 다음과 같다.

```text
목표 이해
  → 코드 조사
  → 사실과 가정 분리
  → 계획 수립 및 검토
  → 작은 단위로 변경
  → 명령과 테스트 실행
  → 전체 diff 검토
  → 수정 또는 완료
```

## 4. 결과보다 판단 과정을 평가한다

테스트가 통과했다는 사실만으로 완료하지 않는다. 학습자는 다음을 설명해야 한다.

- Claude의 최초 제안은 무엇이었는가
- 어떤 근거를 코드와 실행 결과에서 확인했는가
- 어떤 제안을 수정하거나 거절했는가
- 테스트가 발견하지 못할 수 있는 위험은 무엇인가
- 같은 작업을 다시 한다면 지시를 어떻게 개선할 것인가

## 5. 실제 업무와 같은 불확실성을 유지한다

실습 티켓에는 관련 없는 정보나 불완전한 증상이 포함될 수 있다. 반면 실습에 꼭 필요한 결제 지식은 짧은 `Domain Brief`로 제공한다. 도메인 지식 부족이 Claude 학습의 장애물이 되어서는 안 된다.

## 6. 퇴근 후 학습에 맞춘다

- 한 세션은 60~90분으로 제한한다.
- 각 단계에 명확한 중단 및 재개 지점을 둔다.
- 연속 학습일이나 경쟁형 점수는 사용하지 않는다.
- 완료하지 못한 실습도 조사, 계획, 구현, 검증 상태를 따로 저장한다.
- 힌트는 기다림 없이 필요한 수준까지만 단계적으로 공개한다.

## 콘텐츠 검토 질문

모든 레슨과 실습은 다음 질문을 통과해야 한다.

1. 주 학습 목표가 Claude 역량인가?
2. 학습한 역량을 다른 도메인에서도 사용할 수 있는가?
3. 결제 지식이 부족해도 실습할 수 있는가?
4. Claude가 수행한 일과 개발자가 판단한 일이 구분되는가?
5. 최종 코드뿐 아니라 작업 과정과 검증 방법을 평가하는가?
