# MVP 커리큘럼

과정은 하루 1~2시간씩 학습할 수 있는 8개 세션으로 구성한다. Session 1은 3일 이상으로 나누어 진행할 수 있으며 총 예상 시간은 약 12시간 50분이다.

| 세션 | Claude 학습 주제 | 결제 사례 | 시간 |
|---|---|---|---:|
| 1 | Claude 구조, CLI, JetBrains, 권한, 메모리 이해하기 | 모호한 결제 실패 요청 | 260분 |
| 2 | 근거를 요구하며 코드 탐색하기 | 주문에서 PSP까지의 흐름 | 60분 |
| 3 | 요구사항을 작업 계획으로 바꾸기 | 결제 요청 멱등성 | 75분 |
| 4 | 작은 단위로 구현하고 검증하기 | 멱등성 구현 | 75분 |
| 5 | Claude의 가정을 검증하며 디버깅하기 | PSP 처리 후 응답 유실 | 90분 |
| 6 | 실패 조건을 이용해 결과 검증하기 | 중복 Webhook | 75분 |
| 7 | Claude와 의견이 다를 때 판단하기 | 순서가 뒤바뀐 이벤트 | 75분 |
| 8 | 나만의 Claude 개발 워크플로 만들기 | 전체 변경 사항 리뷰 | 60분 |

## 공통 세션 리듬

```text
지난 내용 확인       5분
핵심 개념       10~15분
Claude와 실습   35~55분
검증 및 리뷰    10~15분
진행 상태 저장       5분
```

## Session 1. Claude를 올바르게 이해하기

학습 목표:

- Claude와 전통적인 개발 도구의 차이를 설명한다.
- Claude가 프로젝트 전체를 자동으로 알고 있지 않은 이유를 이해한다.
- 응답 생성과 사실 확인을 구분한다.
- Claude 웹과 Claude Code의 역할을 구분한다.
- CLI 명령, 권한 모드와 JetBrains 연결 방식을 익힌다.
- 컨텍스트, 세션, 메모리와 `CLAUDE.md`를 구분한다.
- 지원되는 private gateway와 Desktop의 연결 전제를 이해한다.
- 개발자의 최종 검증 책임을 이해한다.

완료 조건:

- 사전 준비 페이지에서 Claude Code 설치와 로그인을 확인한다.
- 모호한 결제 실패 요청에 부족한 정보를 식별한다.
- 조사와 구현을 분리한 첫 요청을 작성한다.
- 개인 Claude 개발 원칙을 한 문장으로 기록한다.

## Session 2. 근거를 요구하며 코드 탐색하기

학습 목표:

- 코드 변경 없이 조사만 요청한다.
- 주장에 파일과 코드 위치의 근거를 요구한다.
- 확인된 사실과 확인되지 않은 가정을 분리한다.

완료 조건:

- 결제 요청의 진입점을 찾는다.
- 주문에서 PSP까지의 호출 흐름을 설명한다.
- 주요 도메인 상태와 트랜잭션 경계를 식별한다.
- 추가 확인이 필요한 가정 목록을 작성한다.

## Session 3. 요구사항을 작업 계획으로 바꾸기

학습 목표:

- 모호한 요구사항을 검증 가능한 완료 조건으로 바꾼다.
- 구현 전 영향 범위와 기존 패턴을 조사한다.
- Claude의 계획에서 누락과 과도한 변경을 발견한다.

완료 조건:

- 정상, 중복, 충돌 및 동시 요청을 구분한다.
- 구현 계획과 테스트 시나리오를 작성한다.
- Claude의 계획에서 수정한 부분을 기록한다.

## Session 4. 작은 단위로 구현하고 검증하기

학습 목표:

- 승인된 계획을 작은 변경 단위로 실행한다.
- 테스트 결과와 전체 diff를 직접 확인한다.
- 불필요한 변경을 발견하고 제거한다.

완료 조건:

- 결제 요청 멱등성을 구현한다.
- 단위 및 통합 테스트를 실행한다.
- 데이터베이스 제약과 동시 요청을 검토한다.

## Session 5. Claude의 가정을 검증하며 디버깅하기

학습 목표:

- 증상과 원인을 분리한다.
- 여러 가설을 만들고 코드와 로그로 검증한다.
- 위험한 최초 해결책을 거절하고 근거를 설명한다.

완료 조건:

- 처리 전 타임아웃과 처리 후 타임아웃을 구분한다.
- 무조건 재시도가 위험한 이유를 설명한다.
- 불확실한 결제 상태와 후속 확인 전략을 구현한다.

## Session 6. 실패 조건을 이용해 결과 검증하기

학습 목표:

- 정상 경로 외의 테스트를 요청한다.
- Claude가 놓친 경계 조건을 찾는다.
- 생성된 테스트 자체가 요구사항을 검증하는지 확인한다.

완료 조건:

- 동일 Webhook 이벤트의 재처리를 방지한다.
- 트랜잭션 실패 후 재수신을 고려한다.
- 처리 및 무시 결과를 추적할 수 있게 한다.

## Session 7. Claude와 의견이 다를 때 판단하기

학습 목표:

- 여러 해결안과 트레이드오프를 비교한다.
- 과도한 추상화와 잘못된 방향을 발견한다.
- 컨텍스트와 계획을 재정리해 작업을 복구한다.

완료 조건:

- 허용되는 상태 전이를 정의한다.
- 뒤늦은 이벤트가 상태를 과거로 되돌리지 않게 한다.
- 무시한 이벤트를 추적하고 상태 전이 테스트를 작성한다.

## Session 8. 나만의 Claude 개발 워크플로 만들기

학습 목표:

- 전체 변경을 독립적으로 평가한다.
- 보안, 성능, 정합성 및 운영 가능성을 검토한다.
- 개인 업무에 재사용할 Claude 작업 절차를 만든다.

완료 조건:

- 핵심 실습 하나의 전체 diff를 다시 리뷰한다.
- 테스트되지 않은 실패 경로를 기록한다.
- 개인 Claude 개발 워크플로와 프로젝트 지침을 완성한다.
