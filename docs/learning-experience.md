# 학습 경험 설계

## 제공 방식

사이트는 개념, 실습 요구사항, 힌트, 검증 체크리스트와 회고 질문을 제공한다. 학습자는 별도 `globalpay-commerce-lab` 저장소를 내려받아 IntelliJ IDEA, 터미널, Claude Code 및 Docker Compose를 사용한다.

브라우저 내 IDE, Claude 실행 또는 서버 자동 채점은 MVP에 포함하지 않는다.

## 레슨 구조

1. 학습 목표
2. 시작 업무 사례
3. 핵심 개념
4. 결제 도메인 요약
5. 짧은 예제
6. 개념 확인 문제
7. 다음 실습과의 연결

## 실습 구조

```text
상황 → 조사 → 계획 → 구현 → 검증 → 리뷰 → 회고
```

각 실습은 다음을 제공한다.

- 실제 업무 티켓 형태의 상황 설명
- 현재 시스템 상태와 완료 조건
- 실습에 필요한 최소 `Domain Brief`
- 시작 Git 태그와 브랜치 생성 명령
- 실행할 검증 명령
- 단계별 힌트
- 코드 리뷰 체크리스트
- 참고 구현과 비교 질문
- 추가 도전 과제

## 단계적 힌트

힌트는 기다림이나 강제 잠금 없이 필요한 수준까지 공개한다.

1. 관찰 힌트: 무엇을 확인해야 하는가
2. 분석 힌트: 어떤 코드와 개념을 연결해야 하는가
3. 해결 힌트: 고려할 수 있는 구현 전략
4. 참고 구현: 실습 후 비교와 리뷰에 사용

힌트를 열기 전에 학습자가 다음을 생각하도록 유도한다.

- 현재까지 확인한 사실은 무엇인가
- 아직 확인하지 못한 가정은 무엇인가
- Claude는 어떤 근거로 해결책을 제안했는가

## 평가 방식

각 실습은 네 가지 자기 평가를 조합한다.

### 1. 개념 확인

세션당 3~5개의 상황 판단형 문항을 제공한다. 정답뿐 아니라 판단 기준과 반례를 설명한다.

### 2. 로컬 테스트

학습자는 명령을 직접 실행하고 테스트가 실제 요구사항을 검증하는지 읽는다. 테스트 통과 결과를 서버로 전송하지 않는다.

### 3. 코드 리뷰

다음 관점을 공통 체크리스트로 사용한다.

- 정확성
- 실패 대응
- 데이터 정합성
- 테스트 범위
- 변경 범위
- 운영 가능성
- 보안
- Claude의 주장과 실제 코드의 일치 여부

각 항목은 `확인하지 않음`, `위험 발견`, `수정 완료`, `해당 없음`으로 기록한다.

### 4. 회고

학습자는 다음을 기록한다.

- Claude의 최초 제안
- 동의하지 않았거나 수정한 부분
- 추가로 필요했던 컨텍스트
- 테스트가 발견한 문제와 발견하지 못할 위험
- 실제 운영이라면 추가로 확인할 내용
- 다음 작업에서 개선할 지시 방식

## 완료 기준

필수:

- 핵심 개념 문제 확인
- 필수 로컬 테스트 실행
- 전체 diff 검토
- 위험 또는 개선점 한 가지 이상 기록
- 회고 작성

선택:

- 추가 실패 테스트 작성
- 참고 구현과 비교
- 다른 설계 대안 검토

과정 전체에는 경쟁형 점수나 등급을 두지 않는다. 핵심 수료 기준은 Claude의 제안을 수정하거나 거절한 근거를 설명하고 자신의 반복 가능한 개발 워크플로를 갖는 것이다.

## 진도와 재개

브라우저에 다음 정보를 저장한다.

- 완료한 레슨과 실습
- 실습 단계별 상태
- 마지막 방문 위치
- 열어본 힌트
- 개인 메모와 회고

진도 초기화 및 JSON 가져오기·내보내기를 제공한다. 연속 학습일 대신 전체 과정과 현재 단계의 진행률을 보여준다.
