# 결제 요청 흐름 추적하기

## Claude 학습 목표

- 넓은 저장소 요약 대신 하나의 실행 흐름을 출발점으로 탐색합니다.
- Claude에게 결과 형식과 증거 수준을 지정합니다.
- 첫 답변에서 멈추지 않고 누락된 연결을 후속 질문으로 좁힙니다.

## 실습 준비

처음 실습한다면 과정 저장소와 같은 상위 디렉터리에 실습 저장소를 복제합니다.

```bash
cd ..
git clone https://github.com/ac2dia/globalpay-commerce-lab.git
```

이미 복제했다면 해당 저장소로 이동해 Session 2 시작 태그를 선택합니다.

```bash
cd ../globalpay-commerce-lab
git status
git checkout lab-02-start
./gradlew test
```

`git status`가 깨끗하고 테스트가 통과하면 Claude Code를 Plan mode로 시작합니다.

```bash
claude --permission-mode plan
```

## Domain Brief

이번 실습에서 알아야 할 내용:

- 주문은 결제 전 `PENDING_PAYMENT`, 승인 후 `PAID`가 됩니다.
- 결제는 PSP 요청 중 `PROCESSING`, 승인 후 `APPROVED`가 됩니다.
- PSP는 외부 결제 처리 사업자이며 실습에서는 로컬 Mock으로 대체합니다.
- `@Transactional`이 붙은 메서드는 조사할 중요한 경계 후보입니다.

주의해야 할 오해:

- 패키지 이름만 보고 실제 호출 순서를 확정하지 않습니다.
- `save` 호출이 보인다는 이유만으로 그 시점에 DB commit이 끝났다고 단정하지 않습니다.
- Mock PSP의 동작을 실제 PSP 계약으로 일반화하지 않습니다.

이번 과정에서 다루지 않는 내용:

- 실제 카드 승인 네트워크
- 국가별 규제와 보안 인증
- 장애·재시도·Webhook 구현

## 업무 티켓

```text
POST /api/payments 요청이 들어온 뒤 주문이 PAID가 되고
Mock PSP 참조 번호가 응답될 때까지의 호출 흐름을 조사하세요.

주요 주문·결제 상태 변경과 트랜잭션 경계도 찾아야 합니다.
아직 코드는 수정하지 않습니다.
```

## 3. 누락을 좁히는 후속 질문

첫 답변에 아래 문제가 있으면 한 번에 전체 조사를 다시 요청하지 말고 해당 연결만 좁혀 질문합니다.

- 파일 경로는 있지만 코드 위치가 없다.
- 컨트롤러에서 서비스까지는 설명했지만 PSP 구현체 선택이 빠졌다.
- 상태 이름은 나열했지만 변경 메서드를 찾지 않았다.
- `@Transactional` 위치와 실제 commit 시점을 같은 것으로 표현했다.
- Java에서 Kotlin으로 넘어가는 호출을 생략했다.
