# 개념 확인과 두 번째 원칙

## 개념 확인

### 1. Plan mode에서 Claude가 설명한 내용은 모두 사실인가요?

<details>
<summary>정답 확인</summary>

아닙니다. Plan mode는 파일 수정을 막는 작업 모드이지 설명의 정확성을 보장하는 검증 장치가 아닙니다. 파일과 코드 위치를 직접 대조해야 합니다.

</details>

### 2. `@Transactional`이 `PaymentService.pay`에 있으면 PSP 호출 전에 PROCESSING 결제가 commit되었다고 확정할 수 있나요?

<details>
<summary>정답 확인</summary>

아닙니다. 현재 코드에서는 PSP 호출이 같은 메서드의 트랜잭션 범위 안에 있습니다. 일반적인 성공 경로의 commit은 메서드가 정상 종료될 때 일어나지만, 실제 동작은 트랜잭션 설정과 예외 조건도 함께 확인해야 합니다.

</details>

### 3. 가장 신뢰할 수 있는 조사 결과는 무엇인가요?

1. Claude가 자신 있게 표현한 설명
2. 일반적인 Spring Boot 관례와 일치하는 설명
3. 파일과 호출 관계를 직접 대조하고 불확실성을 표시한 설명

<details>
<summary>정답 확인</summary>

3번입니다. 관례는 탐색 방향을 잡는 데 유용하지만 현재 저장소의 사실을 대신하지 않습니다.

</details>
