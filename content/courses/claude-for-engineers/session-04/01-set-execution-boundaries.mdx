# 구현 경계와 검증 계약 세우기

## Claude 학습 목표

- Claude가 스스로 확인할 수 있는 성공 조건을 작업 지시에 넣습니다.
- 큰 계획을 테스트 가능한 작은 변경으로 나눕니다.
- 각 단계의 중단 조건과 계획 밖 변경 처리 방법을 정합니다.

## 계획 전체를 한 번에 맡기지 않습니다

다음 요청은 완료 조건이 넓고 검토 시점이 너무 늦습니다.

```text
Session 3 계획대로 결제 멱등성을 전부 구현하고 테스트해 줘.
```

Claude Code 공식 문서는 테스트 사례나 기대 출력처럼 직접 확인할 수 있는 기준을 제공하면 Claude가 작업 결과를 검증하기 쉬워진다고 설명합니다. 이번 세션에서는 하나의 작은 루프를 반복합니다.

```text
행동 하나 선택
  → 실패 테스트 작성
  → 실패 이유 확인
  → 최소 구현
  → 집중 테스트
  → diff 검토
```

## 실습 브랜치 준비

Session 4는 코드를 수정하므로 태그를 detached 상태로 직접 편집하지 않습니다. `lab-04-start` 태그에서 자신의 작업 브랜치를 새로 만듭니다.

### 저장소가 아직 없는 경우

```bash
cd ..
git clone https://github.com/ac2dia/globalpay-commerce-lab.git
cd globalpay-commerce-lab
git fetch --tags
git switch -c session-04-work lab-04-start
```

### Session 3에서 이어서 진행하는 경우

Session 3은 코드 변경이 없어야 합니다. 먼저 상태를 확인하세요.

```bash
cd ../globalpay-commerce-lab
git status --short
```

출력이 비어 있을 때 작업 브랜치를 만듭니다.

```bash
git fetch --tags
git switch -c session-04-work lab-04-start
```

`session-04-work` 브랜치가 이미 있다면 새로 만들지 말고 기존 브랜치로 돌아갑니다.

```bash
git switch session-04-work
```

### 시작 상태 확인

```bash
git branch --show-current
git merge-base --is-ancestor lab-04-start HEAD
git status --short
./gradlew test
```

브랜치 이름은 `session-04-work`, `git merge-base`의 종료 코드는 0이어야 합니다. 새로 시작했다면 `git status --short` 출력이 비어 있어야 합니다. 브랜치 이름이 충돌하지만 기존 브랜치를 재사용하면 안 되는 경우 날짜나 이니셜을 붙여 새 이름을 사용하세요. 기존 작업을 삭제하거나 덮어쓰지 않습니다.

## 시작 태그와 참고 태그의 역할

```text
lab-04-start
  └─ session-04-work        ← 학습자가 테스트와 구현을 작성하는 브랜치

lab-04-reference            ← 자신의 구현이 끝난 뒤 비교하는 참고 결과
```

- `lab-04-start`: 멱등성 구현 전 코드입니다. 작업 브랜치는 여기에서 만듭니다.
- `session-04-work`: 학습자의 변경을 보존하는 로컬 브랜치입니다.
- `lab-04-reference`: 완성 답안을 강제하는 브랜치가 아니라 비교용 태그입니다.

학습 도중 `lab-04-reference`를 checkout하지 마세요. 자신의 구현과 리뷰가 끝난 뒤 `git diff lab-04-reference -- src/main src/test`로 비교하면 현재 작업을 유지할 수 있습니다.

## 이번 구현에서 고정할 계약

Session 3의 미결 사항 중 이번 교육용 구현에 필요한 내용만 다음과 같이 고정합니다.

| 상황 | 기대 결과 |
|---|---|
| header 없음 | HTTP 400, PSP 호출 없음 |
| 새로운 key와 주문 | HTTP 201, 결제 생성과 PSP 호출 1회 |
| 같은 key와 같은 주문 | HTTP 200, 최초 payment ID 반환, 추가 PSP 호출 없음 |
| 같은 key와 다른 주문 | HTTP 409, 추가 결제와 PSP 호출 없음 |
| 같은 key의 동시 요청 | 두 요청이 같은 payment ID, 결제 1건, PSP 호출 1회 |

처리 중 요청, key 만료와 PSP 타임아웃은 이후 세션 범위로 남깁니다.

## 작업 경계 작성

<LearningNote id="session-04-execution-boundary" prompt="Claude에게 전달할 변경 범위·검증 명령·중단 조건을 작성하세요." multiline />

권장 경계:

- 한 번에 행동 하나만 구현합니다.
- 실패 테스트가 기대한 이유로 실패하는지 먼저 보고합니다.
- 계획에 없던 파일이 필요하면 수정 전에 이유를 설명합니다.
- 집중 테스트 통과 후 멈추고 변경 파일과 diff를 요약합니다.
- commit, push와 다음 단계 진행은 요청하지 않습니다.
