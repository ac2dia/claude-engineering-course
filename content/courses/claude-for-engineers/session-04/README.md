# Session 4 설계: 작게 구현하고 검증하기

## 세션 목표

학습자는 Session 3에서 승인한 계획을 한 번에 구현시키지 않고, 실패 테스트와 최소 코드 변경을 짝지어 실행합니다. 각 단계에서 Claude가 실제 명령 결과를 확인하게 하고, 마지막에는 전체 diff와 데이터 정합성까지 개발자가 독립적으로 검토합니다.

## 실습 환경

- 저장소: `globalpay-commerce-lab`
- 저장소 버전: `v0.3.0`
- 시작 태그: `lab-04-start`
- 참고 태그: `lab-04-reference`
- 기술: Java 21, Spring Boot 3.5, JPA, H2

## 고정한 교육용 계약

- `Idempotency-Key` header는 필수이며 최대 64자다.
- 최초 성공 요청은 HTTP 201을 반환한다.
- 같은 key와 같은 주문의 재요청은 기존 결과와 HTTP 200을 반환한다.
- 같은 key와 다른 주문은 HTTP 409를 반환한다.
- 같은 key의 동시 요청은 결제 한 건과 PSP 호출 한 번만 만든다.
- DB unique constraint가 경쟁 상황의 최종 보장이다.
- key 만료와 PSP 타임아웃 복구는 이번 세션에서 구현하지 않는다.
