# 반대 사례로 검증하고 여섯 번째 원칙 세우기

## 전체 검증

```bash
./gradlew test
git status --short
git diff --stat lab-06-start
git diff lab-06-start
```

Claude에게 구현을 칭찬하거나 요약하는 대신 반증을 요청합니다.

```text
lab-06-start 이후 diff를 읽고 Webhook 멱등성이 깨지는 반대 사례를 찾으세요.
- 같은 event ID의 순차·동시 수신
- 이벤트 저장 뒤 payment 변경 실패
- payment 변경 뒤 transaction commit 실패
- 이미 승인된 payment의 새 event ID
- 처리 결과 또는 무시 이유가 남지 않는 경로

코드는 수정하지 말고 각 위험에 현재 테스트·constraint·transaction 근거를 붙이세요.
근거가 없으면 미검증으로 표시하세요.
```

## 참고 구현 비교

자신의 리뷰가 끝난 뒤 실행합니다.

```bash
git diff lab-06-reference -- src/main src/test
git show --stat lab-06-reference
```

참고 구현은 event ID를 DB 식별자로 사용하고, 수신 기록과 상태 변경을 하나의 transaction에서 처리합니다. 구조가 다르다면 같은 실패 조건을 보장하는 증거가 있는지 비교하세요.

## 완료 체크

- [ ] 정상 경로 밖의 중복·실패·재수신 테스트를 요청했다.
