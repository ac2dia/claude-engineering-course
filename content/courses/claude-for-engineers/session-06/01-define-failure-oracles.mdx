# 중복 Webhook을 실패 조건으로 정의하기

## Claude 학습 목표

- “중복을 처리한다”를 관찰 가능한 성공·실패 조건으로 바꿉니다.
- 정상 응답뿐 아니라 DB 상태와 부수 효과까지 검증 기준에 넣습니다.
- Claude가 만든 테스트가 요구사항을 실제로 증명하는지 리뷰합니다.

## 시작 업무 티켓

```text
PSP가 같은 PAYMENT_APPROVED Webhook을 여러 번 보낼 수 있습니다.
중복 이벤트 때문에 결제가 두 번 처리되지 않도록 해 주세요.
```

이 티켓만으로는 무엇을 같은 이벤트로 볼지, 중복 응답은 무엇인지, 첫 처리가 실패했을 때 재수신을 허용할지 결정할 수 없습니다. 먼저 실패 조건을 작성합니다.

## 실습 브랜치 준비

Session 6는 `lab-06-start`에서 별도 작업 브랜치를 만듭니다. Session 5 구현 위에 직접 이어서 작업하지 않아도 필요한 결제 상태와 Webhook 시작 코드가 태그에 포함되어 있습니다.


## 실패 오라클 작성

이번 세션에서 고정할 계약입니다.

| 입력 | HTTP/결과 | payment·order | 이벤트 기록 |
|---|---|---|---|
| 첫 승인 이벤트 | 200 `PROCESSED` | 승인·결제 완료 | 1건 |
| 같은 event ID 재수신 | 200 `DUPLICATE` | 추가 변경 없음 | 여전히 1건 |
| 처리 도중 transaction 실패 | 오류 응답 | 원래 상태 유지 | 0건 |
| 실패한 동일 이벤트 재수신 | 200 `PROCESSED` | 한 번만 변경 | 1건 |
| 다른 event ID지만 이미 승인됨 | 200 `IGNORED` | 추가 변경 없음 | 무시 이유 기록 |
