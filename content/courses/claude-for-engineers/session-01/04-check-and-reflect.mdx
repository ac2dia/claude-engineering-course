# 개념 확인과 첫 번째 원칙

## 개념 확인

### 1. Claude Code가 프로젝트에 접근할 수 있다는 의미로 가장 적절한 것은?

- A. 시작할 때 모든 파일을 컨텍스트에 넣는다.
- B. 필요한 파일을 도구로 찾아 읽을 수 있다.
- C. 프로젝트의 비즈니스 요구사항을 이미 이해한다.
- D. 코드에 없는 운영 상황도 알 수 있다.

<details>
<summary>답과 해설</summary>

정답은 B입니다. 접근할 수 있다는 것과 관련 파일을 읽고 작업에 필요한 제약을 올바르게 이해했다는 것은 다릅니다.

</details>

### 2. Claude Code의 기본 에이전트 루프는?

- A. 코드 생성 → 커밋 → 배포
- B. 질문 → 정답 → 종료
- C. 컨텍스트 수집 → 행동 → 검증
- D. 계획 → 승인 없는 실행 → 보고

<details>
<summary>답과 해설</summary>

정답은 C입니다. 작업에 따라 세 단계를 여러 번 반복하며 개발자도 중간에 개입할 수 있습니다.

</details>

### 3. 파일 편집 권한을 승인했다면 무엇이 보장됩니까?

- A. 비즈니스 로직이 정확하다.
- B. 변경이 회사 정책에 맞는다.
- C. Claude가 승인된 범위의 행동을 수행할 수 있다.
- D. 테스트가 모든 실패 조건을 검증한다.

<details>
<summary>답과 해설</summary>

정답은 C입니다. 권한은 행동 가능 범위를 통제하지만 결과 품질을 보장하지 않습니다.

</details>

### 4. `CLAUDE.md`에 대한 설명으로 적절한 것은?

- A. Claude가 반드시 지켜야 하는 강제 정책이다.
- B. 프로젝트 지침과 규칙을 매 세션의 컨텍스트로 제공할 수 있다.
- C. 모든 회사 기밀을 저장하는 안전한 비밀 저장소다.
- D. 테스트와 코드 리뷰를 대신한다.

<details>
<summary>답과 해설</summary>

정답은 B입니다. 강제 차단이 필요한 작업은 권한, 관리 설정 또는 hooks 같은 통제 수단을 별도로 검토해야 합니다.

</details>

### 5. 코드 구조만 조사하고 편집을 막고 싶을 때 가장 알맞은 시작은?

- A. `claude --permission-mode plan`
- B. `claude -p`와 권한 우회
- C. Accept edits에서 바로 구현 요청
- D. Desktop에 토큰을 붙여 넣기

<details>
<summary>답과 해설</summary>

정답은 A입니다. Plan mode는 조사와 계획에 유용하지만 분석 정확성을 보장하지는 않으므로 파일 근거를 함께 확인합니다.

</details>

### 6. JetBrains 플러그인 사용 준비로 올바른 것은?

- A. 플러그인만 설치하면 CLI 없이 동작한다.
- B. Claude Code CLI를 별도 설치하고 프로젝트 루트의 터미널에서 시작한다.
- C. 열린 모든 파일은 자동으로 안전하게 공유된다.
- D. 처음부터 Bypass permissions를 사용한다.

<details>
<summary>답과 해설</summary>

정답은 B입니다. 선택 영역과 열린 파일에 민감 정보가 없는지도 확인하고 처음에는 Manual 또는 Plan mode를 사용합니다.

</details>

### 7. private network의 Desktop 연결 설명으로 올바른 것은?

- A. CLI의 `ANTHROPIC_BASE_URL`이 Desktop에도 자동 적용된다.
- B. 임의의 로컬 모델이면 모두 연결된다.
- C. 지원되는 Anthropic API 형식의 gateway가 필요하며 Desktop Developer 설정에서 별도로 구성한다.
- D. 완전한 air-gap에서도 upstream 없이 동작한다.

<details>
<summary>답과 해설</summary>

정답은 C입니다. gateway 호환성, 네트워크 경로, 인증과 데이터 정책을 조직과 먼저 확인해야 합니다.

</details>

### 8. 사내 gateway가 `Authorization: Bearer`로 static private token을 받는다면 올바른 연결은?

- A. CLI는 `ANTHROPIC_API_KEY`, Desktop은 `x-api-key`를 사용한다.
- B. CLI는 `ANTHROPIC_AUTH_TOKEN`, Desktop은 API key와 `Bearer` auth scheme을 사용한다.
- C. token을 `CLAUDE.md`에 기록하면 CLI와 Desktop이 함께 읽는다.
- D. CLI 설정을 마치면 Desktop에도 자동으로 복사된다.

<details>
<summary>답과 해설</summary>

정답은 B입니다. CLI와 Desktop의 설정 위치는 서로 다릅니다. static token을 사용하더라도 저장·회전 정책을 확인하고, 조직 환경에서는 credential helper나 OIDC 같은 중앙 관리 방식을 우선 검토합니다.

</details>

### 9. Claude가 수정한 파일을 checkpoint로 되돌릴 수 있다면 함께 보장되는 것은?

- A. 이미 호출한 운영 API도 취소된다.
- B. push와 배포도 자동으로 되돌아간다.
- C. 로컬 파일 변경을 rewind할 수 있지만 외부 부작용에는 별도 복구가 필요하다.
- D. Git branch가 자동으로 생성된다.

<details>
<summary>답과 해설</summary>

정답은 C입니다. checkpoint는 로컬 파일 편집의 안전망이며 Git, database rollback, API 보상 작업을 대신하지 않습니다.

</details>
