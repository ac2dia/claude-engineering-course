# Session 1 설계: Claude를 올바르게 이해하기

## 세션 목표

학습자는 Claude를 정답 생성기나 코드 자동완성으로 이해하지 않고, 모델이 주어진 컨텍스트를 바탕으로 추론하고 Claude Code가 도구를 사용해 조사·행동·검증하는 구조로 이해한다.

## 예상 시간

| 순서 | 페이지 | 시간 |
|---|---|---:|
| 1 | Claude와 Claude Code 구분하기 | 15분 |
| 2 | 에이전트 루프와 개발자의 역할 | 15분 |
| 3 | 모호한 결제 장애 요청 개선하기 | 20분 |
| 4 | 개념 확인과 회고 | 10분 |
| 합계 |  | 60분 |

환경 설치 시간은 개인 환경에 따라 편차가 크므로 60분에 포함하지 않는다. `/setup`의 사전 준비 체크리스트를 Session 1 진입 조건으로 둔다.

## 페이지 흐름

```text
Claude와 Claude Code 구분
  → 모델·도구·컨텍스트의 관계 이해
  → 모호한 업무 요청 분석
  → 더 나은 첫 요청 작성
  → 개념 확인과 개인 원칙 기록
```

## 핵심 오해 교정

| 오해 | 학습 후의 이해 |
|---|---|
| Claude는 프로젝트 전체를 이미 읽었다 | Claude Code는 프로젝트에 접근할 수 있지만 필요한 파일을 도구로 찾아 읽어야 한다 |
| 구체적인 답변은 사실일 가능성이 높다 | 구체성이나 자신감은 코드 근거가 아니다 |
| 권한을 승인하면 안전한 작업이다 | 권한은 실행 가능 범위를 통제하며 결과의 정확성을 보장하지 않는다 |
| 좋은 프롬프트는 한 번에 완벽해야 한다 | 대화를 통해 조사 결과를 확인하고 방향을 교정할 수 있다 |
| CLAUDE.md는 반드시 지켜지는 정책이다 | CLAUDE.md는 행동을 유도하는 지속 컨텍스트이며 강제 통제와 다르다 |

## Session 1에서 하지 않는 것

- 실제 결제 기능 구현
- 프롬프트 공식 암기
- 컨텍스트 윈도우 크기나 모델별 수치 비교
- 모델 내부 구조에 대한 비공개 정보 추측
- MCP, hooks, skills, subagents의 상세 사용법
- 복잡한 CLAUDE.md 작성

## 선행 조건

- Git 사용 가능
- Claude Code 설치와 로그인 완료
- `claude --version` 실행 가능
- 이후 제공될 `globalpay-commerce-lab` 저장소 준비

실습 저장소가 만들어지기 전에는 세 번째 페이지의 시뮬레이션만으로 콘텐츠를 검토할 수 있다.

## 사이트 구현에 필요한 MDX 컴포넌트

| 컴포넌트 | 역할 | MVP 저장 방식 |
|---|---|---|
| `LearningNote` | 짧은 답변, 개인 원칙 및 회고 기록 | localStorage |
| `ProgressiveHints` | 힌트 영역과 공개 상태 관리 | localStorage |
| `Hint` | 단계별 관찰·분석·해결 힌트 | 상위 컴포넌트 사용 |
| `EndSession` | 완료 확인, 오늘은 여기까지, 다음 세션 안내 | localStorage |

컴포넌트가 아직 구현되지 않은 상태에서도 MDX 원문을 검토할 수 있어야 한다. 사이트 골격을 만들 때 실제 props와 콘텐츠 스키마를 확정한다.

## 콘텐츠 완료 조건

- [ ] 공식 문서 링크와 검토 날짜가 표시된다.
- [ ] 공개 사실과 교육용 정신 모델이 구분된다.
- [ ] 결제 지식 없이도 활동을 진행할 수 있다.
- [ ] 학습자가 Claude의 답변을 그대로 수용하지 않는 경험을 한다.
- [ ] 네 개 페이지의 예상 시간이 합계 60분이다.
- [ ] 모바일보다 데스크톱 읽기 및 코드 비교에 최적화된다.
- [ ] Session 2의 코드베이스 탐색 실습으로 자연스럽게 연결된다.
