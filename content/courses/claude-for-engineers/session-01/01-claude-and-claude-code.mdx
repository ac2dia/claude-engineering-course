# Claude와 Claude Code 구분하기

## 학습 목표

이 페이지를 마치면 다음을 설명할 수 있습니다.

- Claude 모델과 Claude Code의 역할 차이
- 텍스트로 답하는 모델이 파일을 수정하고 테스트를 실행할 수 있는 이유
- 프로젝트에 접근할 수 있다는 것과 프로젝트를 이미 읽었다는 것의 차이

## 참고 자료를 사용하는 기준

이 세션은 제품 동작과 명령의 기준으로 [Claude Code 공식 문서](https://code.claude.com/docs/en/overview)를 우선합니다. [Claude Code 입문 WikiDocs](https://wikidocs.net/book/19202)는 설치→첫 세션→동작 원리→interactive mode→memory 순서와 연습 구조를, [Claude Code 가이드 WikiDocs](https://wikidocs.net/book/19104)는 초보자가 찾아보기 어려운 reference 항목을 선별하는 데 참고했습니다.

Claude Code는 빠르게 바뀌므로 WikiDocs와 이 과정의 단축키·모드 이름이 현재 설치와 다르면 `/help`와 공식 문서를 최종 기준으로 사용합니다. 이 과정의 목표와 직접 관계없는 MCP 구축, hooks 상세 문법, subagent team, CI 자동화는 Session 1에서 제외합니다.

## 먼저 세 가지를 구분합니다

### Claude 모델

Claude 모델은 제공된 입력을 바탕으로 응답을 생성하고 추론합니다. 모델이 학습 과정에서 얻은 일반 지식과 현재 회사 저장소의 사실은 서로 다릅니다. 현재 코드의 상태를 정확히 설명하려면 관련 파일과 실행 결과가 컨텍스트에 들어와야 합니다.

### Claude 인터페이스

Claude 웹은 대화, 문서 분석과 설계 논의에 사용할 수 있는 인터페이스입니다. 사용자가 대화에 제공하지 않은 로컬 저장소를 자동으로 읽는다고 가정해서는 안 됩니다.

### Claude Code

Claude Code는 Claude 모델에 개발 도구와 실행 환경을 연결한 에이전트형 개발 도구입니다. 터미널, IDE, 데스크톱 및 웹 등의 인터페이스에서 사용할 수 있으며, 설정과 권한 범위 안에서 다음과 같은 일을 수행할 수 있습니다.

- 파일과 Git 상태 조사
- 코드 검색과 여러 파일의 관계 파악
- 파일 생성과 수정
- 빌드 및 테스트 명령 실행
- 실행 결과를 다음 판단에 반영

## 교육용 정신 모델

다음 그림은 이해를 돕기 위한 단순화이며 Claude의 비공개 내부 구조를 설명하는 것이 아닙니다.

```text
개발자의 목표와 지시
          │
          ▼
┌──────────────────────────────┐
│ Claude Code                  │
│                              │
│  현재 컨텍스트 → Claude 모델 │
│                     │        │
│                     ▼        │
│              다음 행동 선택 │
│                     │        │
│       파일·검색·실행 도구    │
└─────────────────────┬────────┘
                      │
                      ▼
              코드와 실행 결과
```

Claude 모델은 파일을 직접 만지는 운영체제 프로세스가 아닙니다. Claude Code가 모델에 도구를 제공하고, 도구의 결과를 다시 컨텍스트로 전달합니다.

## 아키텍처를 네 층으로 이해합니다

공식 제품의 비공개 내부 구현을 추측하기보다, 개발자가 통제할 수 있는 경계를 네 층으로 나누면 실무 판단이 쉬워집니다.

| 층 | 예시 | 개발자가 확인할 것 |
|---|---|---|
| 표면 | CLI, JetBrains, Desktop, Web | 어느 프로젝트·세션에서 대화하는가 |
| 에이전트 런타임 | 컨텍스트 구성, 도구 선택, 권한 확인 | 어떤 파일과 명령에 접근을 허용했는가 |
| 모델 | 입력을 해석하고 다음 응답·행동을 제안 | 사실과 추론이 구분되어 있는가 |
| 외부 환경 | 로컬 파일, Git, 셸, MCP, 네트워크 | 결과와 부작용을 독립 검증했는가 |

CLI와 JetBrains가 서로 다른 Claude를 사용하는 것은 아닙니다. 같은 프로젝트 지침을 공유할 수 있지만, 각 세션이 읽은 파일과 대화 이력은 같다고 가정하면 안 됩니다. 또한 MCP나 사내 게이트웨이는 별도 연결 경계이지 모델이 회사 시스템을 원래부터 안다는 뜻이 아닙니다.

## 한 요청이 처리되는 흐름

```text
사용자 요청
  → 현재 대화·프로젝트 지침·선택한 코드가 컨텍스트에 포함됨
  → 모델이 답변 또는 도구 사용을 제안함
  → Claude Code가 권한 규칙을 확인함
  → 허용된 파일·명령 도구가 실행됨
  → 관찰 결과가 다시 컨텍스트에 들어감
  → 모델이 다음 행동 또는 완료 보고를 생성함
```

이 흐름 때문에 좋은 결과는 “좋은 한 문장”만으로 결정되지 않습니다. 올바른 작업 디렉터리, 필요한 근거, 안전한 권한, 검증 명령이 함께 필요합니다.

## 언어 모델을 데이터베이스처럼 다루지 않습니다

Claude 모델은 현재 컨텍스트를 바탕으로 다음 응답과 행동을 생성합니다. 이 특성에서 네 가지 실무 원칙이 나옵니다.

1. **응답은 조회 결과가 아닙니다.** 모델의 일반 지식과 현재 저장소에서 도구로 읽은 사실을 구분합니다.
2. **말투는 신뢰도 점수가 아닙니다.** 확신에 찬 문장도 틀릴 수 있고, 조심스러운 문장도 맞을 수 있습니다.
3. **같은 요청도 과정이 달라질 수 있습니다.** 결정론적인 빌드 스크립트처럼 동일한 도구 순서와 결과를 가정하지 않습니다.
4. **도구 결과가 다음 판단을 바꿉니다.** 첫 추론이 틀려도 테스트 실패와 파일 근거를 제공하면 방향을 교정할 수 있습니다.

따라서 Claude의 “생각을 믿는가?”보다 “어떤 관찰을 했고 무엇으로 검증했는가?”를 묻습니다. 내부 reasoning 전문을 요구하는 대신, 결론을 뒷받침하는 파일·명령·테스트와 남은 불확실성을 요청하세요.

## 실행 환경과 인터페이스도 분리합니다

| 구분 | 선택지 | 핵심 질문 |
|---|---|---|
| 실행 환경 | local, cloud, Remote Control | 코드는 어디에서 실행되고 어떤 파일·자격 증명에 닿는가 |
| 인터페이스 | CLI, JetBrains, Desktop, Web | 개발자는 어디에서 prompt, diff, 승인 요청을 확인하는가 |

화면이 Desktop이라고 코드가 항상 cloud에서 실행되는 것도 아니고, 브라우저를 쓴다고 항상 local인 것도 아닙니다. 회사 환경에서는 인터페이스보다 실행 위치, 데이터 경로와 권한 경계를 먼저 확인합니다.

## 접근 가능, 읽음, 이해함은 다릅니다

Claude Code를 저장소 루트에서 실행하면 프로젝트 파일과 Git 상태를 조사할 수 있습니다. 하지만 다음 세 문장은 같은 뜻이 아닙니다.

1. Claude Code가 파일에 접근할 수 있다.
2. Claude가 관련 파일을 실제로 읽었다.
3. Claude가 요구사항에 필요한 관계와 제약을 올바르게 이해했다.

따라서 “저장소를 이해했어?”보다 다음과 같이 근거를 요구하는 편이 좋습니다.

```text
아직 코드를 수정하지 마세요.

결제 요청의 진입점부터 PSP 호출까지의 흐름을 조사하세요.
각 주장에는 근거가 되는 파일 경로와 코드 위치를 제시하고,
현재 코드만으로 확인할 수 없는 내용은 가정으로 분리하세요.
```

## 공개된 사실과 실무 해석

**공개된 사실:** 공식 문서는 Claude Code가 코드베이스를 읽고, 파일을 수정하고, 명령을 실행하는 에이전트형 코딩 도구라고 설명합니다.

**실무 해석:** “코드베이스를 이해한다”는 표현을 무조건적인 완전한 이해로 받아들이지 않습니다. 현재 작업에 필요한 파일을 충분히 조사했는지 근거로 확인해야 합니다.

## 잠깐 확인하기

다음 중 프로젝트에 대한 가장 강한 근거는 무엇일까요?

1. Claude가 확신하는 표현으로 설명했다.
2. 일반적인 Spring Boot 구조와 비슷하다고 설명했다.
3. 관련 파일과 테스트를 읽고 경로와 실행 결과를 제시했다.

정답은 3번입니다. 구체적인 말투보다 현재 저장소에서 얻은 증거가 중요합니다.
