# Claude와 Claude Code 구분하기

## 학습 목표

이 페이지를 마치면 다음을 설명할 수 있습니다.

- Claude 모델과 Claude Code의 역할 차이
- 텍스트로 답하는 모델이 파일을 수정하고 테스트를 실행할 수 있는 이유
- 프로젝트에 접근할 수 있다는 것과 프로젝트를 이미 읽었다는 것의 차이

## 시작 질문

동료가 다음과 같이 말했습니다.

> Claude가 우리 저장소를 이해했으니 결제 버그 수정을 맡겨도 되겠네요.

여기에는 어떤 가정이 숨어 있을까요? 답을 읽기 전에 두 가지 이상 적어보세요.

## 먼저 세 가지를 구분합니다

### Claude 모델

Claude 모델은 제공된 입력을 바탕으로 응답을 생성하고 추론합니다. 모델이 학습 과정에서 얻은 일반 지식과 현재 회사 저장소의 사실은 서로 다릅니다. 현재 코드의 상태를 정확히 설명하려면 관련 파일과 실행 결과가 컨텍스트에 들어와야 합니다.

### Claude 인터페이스

Claude 웹은 대화, 문서 분석과 설계 논의에 사용할 수 있는 인터페이스입니다. 사용자가 대화에 제공하지 않은 로컬 저장소를 자동으로 읽는다고 가정해서는 안 됩니다.

### Claude Code

Claude Code는 Claude 모델에 개발 도구와 실행 환경을 연결한 에이전트형 개발 도구입니다. 터미널, IDE, 데스크톱 및 웹 등의 인터페이스에서 사용할 수 있으며, 설정과 권한 범위 안에서 다음과 같은 일을 수행할 수 있습니다.

- 파일과 Git 상태 조사
- 코드 검색과 여러 파일의 관계 파악
- 파일 생성과 수정
- 빌드 및 테스트 명령 실행
- 실행 결과를 다음 판단에 반영

## 교육용 정신 모델

다음 그림은 이해를 돕기 위한 단순화이며 Claude의 비공개 내부 구조를 설명하는 것이 아닙니다.

```text
개발자의 목표와 지시
          │
          ▼
┌──────────────────────────────┐
│ Claude Code                  │
│                              │
│  현재 컨텍스트 → Claude 모델 │
│                     │        │
│                     ▼        │
│              다음 행동 선택 │
│                     │        │
│       파일·검색·실행 도구    │
└─────────────────────┬────────┘
                      │
                      ▼
              코드와 실행 결과
```

Claude 모델은 파일을 직접 만지는 운영체제 프로세스가 아닙니다. Claude Code가 모델에 도구를 제공하고, 도구의 결과를 다시 컨텍스트로 전달합니다.

## 접근 가능, 읽음, 이해함은 다릅니다

Claude Code를 저장소 루트에서 실행하면 프로젝트 파일과 Git 상태를 조사할 수 있습니다. 하지만 다음 세 문장은 같은 뜻이 아닙니다.

1. Claude Code가 파일에 접근할 수 있다.
2. Claude가 관련 파일을 실제로 읽었다.
3. Claude가 요구사항에 필요한 관계와 제약을 올바르게 이해했다.

따라서 “저장소를 이해했어?”보다 다음과 같이 근거를 요구하는 편이 좋습니다.

```text
아직 코드를 수정하지 마세요.

결제 요청의 진입점부터 PSP 호출까지의 흐름을 조사하세요.
각 주장에는 근거가 되는 파일 경로와 코드 위치를 제시하고,
현재 코드만으로 확인할 수 없는 내용은 가정으로 분리하세요.
```

## 공개된 사실과 실무 해석

**공개된 사실:** 공식 문서는 Claude Code가 코드베이스를 읽고, 파일을 수정하고, 명령을 실행하는 에이전트형 코딩 도구라고 설명합니다.

**실무 해석:** “코드베이스를 이해한다”는 표현을 무조건적인 완전한 이해로 받아들이지 않습니다. 현재 작업에 필요한 파일을 충분히 조사했는지 근거로 확인해야 합니다.

## 잠깐 확인하기

다음 중 프로젝트에 대한 가장 강한 근거는 무엇일까요?

1. Claude가 확신하는 표현으로 설명했다.
2. 일반적인 Spring Boot 구조와 비슷하다고 설명했다.
3. 관련 파일과 테스트를 읽고 경로와 실행 결과를 제시했다.

정답은 3번입니다. 구체적인 말투보다 현재 저장소에서 얻은 증거가 중요합니다.
