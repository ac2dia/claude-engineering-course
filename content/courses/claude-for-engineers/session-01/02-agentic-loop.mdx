# 에이전트 루프와 개발자의 역할

## 학습 목표

- Claude Code의 기본 작업 루프를 설명합니다.
- 도구 권한과 결과 정확성을 구분합니다.
- 컨텍스트에 포함되는 정보와 포함되지 않은 정보를 생각합니다.
- 개발자가 루프에 개입해야 하는 지점을 찾습니다.

## Claude Code의 기본 루프

공식 문서는 Claude Code의 에이전트 루프를 다음 세 단계로 설명합니다.

```text
컨텍스트 수집 → 행동 → 결과 검증
       ▲                   │
       └───────────────────┘
```

예를 들어 “실패하는 결제 테스트를 수정해 주세요”라는 요청은 다음과 같이 진행될 수 있습니다.

1. 테스트를 실행해 실패를 재현합니다.
2. 오류 메시지와 관련 코드를 읽습니다.
3. 가능한 원인을 추론합니다.
4. 파일을 수정합니다.
5. 테스트를 다시 실행합니다.
6. 결과에 따라 추가 조사하거나 완료를 보고합니다.

이 순서는 고정된 자동화 스크립트가 아닙니다. Claude는 앞선 도구 결과를 바탕으로 다음 행동을 선택합니다. 잘못된 단서나 가정도 다음 판단에 영향을 줄 수 있습니다.

## 개발자는 루프 밖에 있지 않습니다

개발자는 다음 지점에서 개입할 수 있습니다.

| 단계 | 개발자가 확인할 질문 |
|---|---|
| 목표 이해 | 문제와 완료 조건을 올바르게 이해했는가? |
| 컨텍스트 수집 | 관련 코드와 테스트를 충분히 읽었는가? |
| 가정과 계획 | 코드로 확인하지 않은 내용을 사실처럼 취급하지 않았는가? |
| 행동 | 변경 범위와 실행 명령이 안전한가? |
| 검증 | 테스트가 실제 요구사항을 검증하는가? |
| 완료 보고 | 전체 diff와 남은 위험을 확인했는가? |

Claude가 진행 중일 때도 중단하거나 추가 정보를 제공해 방향을 바꿀 수 있습니다. 처음 요청이 완벽할 필요는 없지만, 잘못된 방향을 알아차리고 교정하는 책임은 사라지지 않습니다.

## 현재 컨텍스트는 작업 기억입니다

Claude Code의 컨텍스트에는 대화 기록, 읽은 파일 내용, 명령 출력, 프로젝트 지침, 메모리 및 시스템 지침 등이 함께 들어갑니다. 컨텍스트에는 한계가 있으며 긴 작업에서는 오래된 도구 출력이 제거되거나 대화가 요약될 수 있습니다.

여기서 중요한 구분은 다음과 같습니다.

```text
모델이 일반적으로 알고 있는 것
≠ 현재 저장소에서 확인한 것
≠ 이번 대화의 컨텍스트에 남아 있는 것
```

지속적으로 필요한 프로젝트 규칙은 대화에서 매번 반복하기보다 `CLAUDE.md`에 둘 수 있습니다. 다만 공식 문서가 설명하듯 `CLAUDE.md`는 Claude에게 제공되는 컨텍스트이며 강제 정책이 아닙니다.

## 권한은 안전장치이지 품질 보증서가 아닙니다

Claude Code는 파일 편집이나 명령 실행 등에 대해 권한을 요청하고 조직이나 사용자가 허용·질문·거부 규칙을 설정할 수 있습니다. 권한 시스템은 Claude가 할 수 있는 행동의 범위를 통제합니다.

하지만 다음은 보장하지 않습니다.

- 수정한 비즈니스 로직의 정확성
- 테스트의 충분성
- 트랜잭션과 동시성 안전성
- 명령이 회사 정책에 적합한지에 대한 최종 판단
- 원격 API나 배포처럼 되돌리기 어려운 부작용의 복구

따라서 권한 요청을 승인하기 전에는 “Claude가 요청했다”가 아니라 명령과 대상, 예상되는 부작용을 확인해야 합니다.

## 사실과 가정 분류하기

다음 문장을 `확인된 사실`, `추론`, `아직 모름`으로 분류해 보세요.

```text
A. PaymentService.java에 retryPayment 메서드가 있다.
B. 이 메서드는 PSP 타임아웃 문제를 해결하기 위해 추가된 것 같다.
C. 운영 환경에서 이 메서드가 실제로 호출되고 있다.
```

예상 분류:

- A는 파일을 실제로 읽었다면 확인된 사실입니다.
- B는 커밋이나 문서 등의 근거가 없다면 추론입니다.
- C는 운영 로그나 추적 정보가 없다면 아직 모릅니다.
