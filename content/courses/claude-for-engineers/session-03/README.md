# Session 3 설계: 요구사항을 작업 계획으로 바꾸기

## 세션 목표

학습자는 결제 요청 멱등성 티켓을 곧바로 구현하지 않고, Claude와 함께 모호한 문장을 행동 예시와 완료 조건으로 바꿉니다. 현재 코드의 영향 범위를 조사하고, Claude가 만든 계획에서 누락·근거 없는 결정·과도한 설계를 찾아 수정합니다.

## 예상 시간

| 순서 | 페이지 | 시간 |
|---|---|---:|
| 1 | 요구사항을 행동 표로 바꾸기 | 15분 |
| 2 | 계획 전에 영향 범위 조사하기 | 20분 |
| 3 | Claude의 작업 계획 리뷰하기 | 25분 |
| 4 | 개념 확인과 회고 | 15분 |
| 합계 |  | 75분 |

## 실습 환경

- 저장소: `globalpay-commerce-lab`
- 저장소 버전: `v0.2.0`
- 시작 태그: `lab-03-start`
- 업무 티켓: `docs/tickets/payment-idempotency.md`
- 변경 허용: 없음. 이번 세션은 요구사항 분석과 계획 검토 전용이다.

## 핵심 산출물

1. 정상·중복·충돌·동시 요청 행동 표
2. 결정된 요구사항·가정·미결 질문 목록
3. 코드 근거가 포함된 영향 범위 지도
4. 검증 순서가 포함된 작은 작업 계획
5. Claude의 최초 계획에서 개발자가 수정한 내용

## 완료 조건

- [ ] 모호한 티켓을 관찰 가능한 행동과 완료 조건으로 바꿨다.
- [ ] 코드에 있는 사실과 제품 결정이 필요한 질문을 분리했다.
- [ ] 기존 API, 엔티티, 저장소, 트랜잭션과 테스트의 영향 범위를 조사했다.
- [ ] 동시 요청을 애플리케이션 메모리가 아닌 DB 정합성 관점에서도 검토했다.
- [ ] Claude의 계획을 그대로 승인하지 않고 최소 한 부분을 수정하거나 근거와 함께 승인했다.
- [ ] 코드 변경 없이 세션을 마쳤다.
