# 참고 결과 비교와 최종 원칙

## 자신의 결과부터 검증합니다

```bash
git status --short
git diff --stat lab-08-start
git diff lab-08-start -- CLAUDE.md docs
./gradlew test
```

리뷰 문서에 적은 명령과 테스트를 실제로 실행했는지, `CLAUDE.md`가 현재 저장소 사실과 일치하는지 확인합니다.

## 참고 결과는 마지막에 봅니다

```bash
git diff lab-08-reference -- CLAUDE.md docs/reviews
git show lab-08-reference:CLAUDE.md
git show lab-08-reference:docs/reviews/session-08-payment-resilience-review-example.md
```

참고 리뷰는 Webhook 인증 부재를 확인된 결함으로, 서로 다른 상충 이벤트의 동시 수신을 높은 우선순위의 미검증 위험으로 분류합니다. 자신의 우선순위가 다르다면 근거와 운영 전제를 비교하세요.

## 과정 완료 체크

- [ ] 핵심 결제 변경의 전체 diff를 독립적으로 다시 리뷰했다.
- [ ] 보안·성능·정합성·운영 관점의 근거 수준을 구분했다.
- [ ] 테스트되지 않은 실패 경로와 다음 검증을 기록했다.
- [ ] 실제 업무에 반복할 개인 Claude 개발 워크플로를 완성했다.
- [ ] 간결하고 검증 가능한 프로젝트 `CLAUDE.md`를 작성했다.
- [ ] 참고 결과와 다른 선택을 이유와 함께 설명할 수 있다.

## 과정 이후

완성한 워크플로를 작은 실제 업무에 적용하고 회고 때마다 한 항목만 조정하세요. 지침이 길어지면 더 추가하기보다 중복되거나 지켜지지 않는 규칙을 먼저 제거합니다. Claude의 출력 품질보다 자신의 검증 루프가 얼마나 일관되게 작동했는지를 측정하세요.
