# 수정 전에 PSP 응답 유실 재현하기

## Claude 학습 목표

- 장애 설명을 곧바로 수정 지시로 바꾸지 않고 재현 가능한 관찰로 만듭니다.
- 증상, 확인된 사실, 아직 검증하지 않은 가정을 분리합니다.
- Claude에게 조사 범위와 중단 조건을 명시합니다.

## 시작 업무 티켓

```text
PSP 호출이 timeout이면 고객은 실패를 보지만 PSP에는 승인이 남아 있습니다.
같은 Idempotency-Key로 재시도하면 PSP 승인이 한 번 더 발생할 수 있습니다.
원인을 확인하고 중복 승인을 막아 주세요.
```

이 문장은 중요한 정보를 주지만 timeout의 발생 시점과 PSP의 최종 상태를 확정하지 않습니다. 먼저 코드가 만들어 내는 모순을 재현합니다.

## 실습 브랜치 준비

Session 5는 코드를 수정하므로 `lab-05-start`에서 개인 작업 브랜치를 만듭니다. Session 4 작업 브랜치 위에 이어서 구현하지 않습니다.

### 저장소가 아직 없는 경우

```bash
cd ..
git clone https://github.com/ac2dia/globalpay-commerce-lab.git
cd globalpay-commerce-lab
git fetch --tags
git switch -c session-05-work lab-05-start
```

### 저장소가 이미 있는 경우

```bash
cd ../globalpay-commerce-lab
git status --short
git fetch --tags
git switch -c session-05-work lab-05-start
```

`git status --short`에 출력이 있다면 먼저 자신의 변경을 commit하거나 stash할지 판단하세요. 기존 변경을 삭제하지 않습니다. `session-05-work`가 이미 있다면 `git switch session-05-work`로 돌아갑니다.

### 시작 상태 검증

```bash
git branch --show-current
git merge-base --is-ancestor lab-05-start HEAD
git status --short
./gradlew test --tests '*PspTimeoutCharacterizationTest'
```

브랜치는 `session-05-work`, `merge-base` 종료 코드는 0이어야 합니다. 테스트는 통과하지만 이름과 assertion을 읽어 보면 현재 결함을 기록한 **특성 테스트**임을 알 수 있습니다.

```text
lab-05-start
  └─ session-05-work        ← 조사·테스트·구현을 보존할 개인 브랜치

lab-05-reference            ← 자신의 리뷰가 끝난 후 비교할 참고 결과
```

학습 도중 `lab-05-reference`를 checkout하지 마세요. 마지막에 `git diff lab-05-reference -- src/main src/test`로 비교하면 작업 브랜치를 유지할 수 있습니다.

## Claude에게 재현만 요청하기

```text
PspTimeoutCharacterizationTest와 관련 제품 코드를 읽으세요.
아직 코드를 수정하지 마세요.

각 테스트가 재현하는 외부 PSP 상태, 로컬 payment row, order 상태를 표로 정리하고
그 결과를 만드는 호출 순서와 transaction 경계를 파일 경로와 메서드명으로 제시하세요.
집중 테스트를 실행해 관찰과 일치하는지 확인한 뒤 멈추세요.
```
