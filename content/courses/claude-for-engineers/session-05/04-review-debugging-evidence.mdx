# 디버깅 증거 검토와 다섯 번째 원칙

## 전체 검증

```bash
./gradlew test
git status --short
git diff --stat lab-05-start
git diff lab-05-start
```

Claude에게 수정 없이 반대 관점의 리뷰를 요청합니다.

```text
lab-05-start 이후 전체 diff를 읽고 이 해결책을 반증하려는 리뷰를 하세요.
- timeout 전·후 PSP 상태를 혼동한 곳
- UNKNOWN인데 성공이나 실패로 단정하는 경로
- 같은 key가 PSP를 다시 호출할 수 있는 경로
- transaction proxy가 적용되지 않을 가능성
- 후속 조회와 order 상태 전이의 원자성
- 테스트하지 않은 실패 조건

코드는 수정하지 말고 각 주장에 파일 경로와 테스트 근거를 붙이세요.
```

## 참고 구현과 비교

자신의 구현과 리뷰가 끝난 뒤 실행합니다.

```bash
git diff lab-05-reference -- src/main src/test
git show --stat lab-05-reference
```

구조가 다르더라도 다음 질문에 같은 수준의 답이 있는지 비교하세요.

- PSP 호출 전에 재전송을 식별할 payment가 남는가?
- 외부 결과를 모르는 동안 어떤 상태가 truth를 보존하는가?
- 후속 조회가 중복 charge가 아니라 status query인가?
- 승인 확인과 order 변경이 함께 commit되는가?
